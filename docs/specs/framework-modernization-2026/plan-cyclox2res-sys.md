# cyclox2res-sys 改修計画（CodeIgniter 3.1.x → サポート圏）

> 親: [README.md](README.md) ／ 役割: 成績**閲覧アプリ（読み取り主体・同一DB `cyclox2` を参照）**

---

## 1. 回収のゴール地点（水準別）

| 水準 | 移行先 | 明確なゴール（完了の定義） |
|---|---|---|
| **(つなぎ)** | CodeIgniter **3.1.13** + PHP **8.1** | 最小改修でサポートPHPに載せ替え（**当座のリスク低減**）。CI3自体はEOLのため恒久解ではない。 |
| **S2** | CodeIgniter **4** + PHP **8.3** | 全閲覧機能がCI4/PHP8.3で現行同一の表示。DB不変。最低限のリグレッションテスト常設。 |
| **S3a** | **Laravel 12** + PHP **8.3**（別アプリ維持） | 同上に加えEloquent化・テスト/CI整備。cyclox2webとスタックを1本化。 |
| **S3b ★採用** | **Laravel 12**（共有ドメインパッケージを利用・**別サーバーで独立デプロイ**） | 成績閲覧を独立 Laravel アプリとして維持しつつ、共有DBのモデル/集計ロジックは**共有Composerパッケージ**を read-only で利用。二重実装を解消しデプロイは分離。 |

**採用**: S3b（PHP 8.3 + Laravel 12）。**res-sys は別サーバーで起動する独立デプロイ**を維持（モノレポ/単一統合にしない）。共有ロジックは共有パッケージから取り込む（[README §4.1](README.md#41-s3b-の実装形態共有パッケージ2デプロイ)）。

**全水準共通の不変条件**: DBスキーマ不変／公開URL・表示の等価／scss(`main.scss`)由来のデザイン維持。

**S3b 固有の責務**: res-sys は **read-only DB接続**で共有パッケージの読みモデル/集計サービスを利用。**スキーマは保有せず**（マイグレーション所有は cyclox2web 側）。8081 で従来どおり独立公開。

## 2. 影響範囲

### 機能領域（6コントローラ / 10モデル / 30ビュー）
- Pages（静的/トップ）, Racer（選手成績）, Race(400行・レース結果), Meet（大会）, Point_series, Ajocc_ranking（ランキング）
- モデル: Pointseries_model(393行) / Race_model / Categoryracer_model / Ajoccranking_model / Result_model 等（**集計クエリが中心**）
- View: templates/(header/footer) ＋ 機能別。helper は `html_escape_helper` のみ。
- ビルド: `scss/main.scss`（CSS生成）, `bin/`（ローカル実行スクリプト群）

### 外部結合・運用面
- **読み取り専用**で cyclox2web が書いた成績DBを参照 → **書き込み副作用なし＝失敗時の影響が限定的**（先行移行に適する）。
- 公開ポート 8081 / `config.php`・`database.php`・`index.php` を docker-compose でマウント。
- 認証は限定的（公開閲覧中心）。Acl等の重い権限機構なし。

## 3. リスク評価

| # | リスク | 影響 | 度合 | 対策（安全圏） |
|---|---|---|---|---|
| R1 | 自動テスト皆無 | 中 | 高 | HTTPゴールデン（主要閲覧URLのレスポンス固定）を整備 |
| R2 | 集計クエリ（Pointseries/Ranking）の結果差異 | 中 | 中 | 代表データで出力突合。SQLは極力そのまま移植 |
| R3 | CI3→CI4は直接アップグレード不可（再実装） | 中 | 中 | 規模小のため垂直スライスで短期完了可 |
| R4 | DBスキーマ変更による cyclox2web 巻き添え | 高 | 低 | スキーマ不変を絶対制約 |
| R5 | 表示崩れ（scss/テンプレート移行） | 低 | 中 | 画面スクリーンショット比較で回帰確認 |

> 読み取り専用ゆえ R は総じて cyclox2web より軽い。**両アプリ刷新の「先行パイロット」**として最適。

## 4. 安全圏を前提とした作業・タスク計画

**P0. 足場（水準共通）**
- PHP 8.x ターゲットコンテナ追加（旧と並行）。
- 主要閲覧URLのHTTPゴールデン取得（Pages/Racer/Race/Meet/Point_series/Ranking）。

**(任意) Pつなぎ. CI3.1.13 + PHP8.1 延命**
- composer を `codeigniter/framework:3.1.13` に更新、PHP8.1非互換箇所（`each()`・動的プロパティ・mysql_*等）を修正。
- 数日規模でサポートPHPに載せ、本移行までの時間を確保。

**P1. 移行先足場**
- S2: CI4 初期化、DB接続、ベースcontroller/モデル、ルーティング、scssビルド導線。
- S3: Laravel 12 初期化、Eloquent（既存スキーマmap）、Blade化土台。

**P2. 機能スライス移行（優先度順）**
1. テンプレート（header/footer）＋ Pages
2. Racer / Race（結果表示・最重要）
3. Meet
4. Point_series
5. Ajocc_ranking（集計）

各スライスで 移植 → ゴールデン/画面突合 → レビュー → 切替。

**P3. 結合・表示・性能テスト → 8081 切替 → 旧停止**

## 6. 推奨（採用方針 S3b に基づく）

- **先行パイロットとして res-sys を最初に Laravel 化**し、テスト手法・移行パターン・read-only接続・コンテナ/独立デプロイ構成を確立 → cyclox2web へ展開。
- まず S3a 相当（独立 Laravel アプリ）として成立させ、cyclox2web 側で共有パッケージが整い次第、res-sys の自前モデル/集計を**共有パッケージ参照へ置換**して S3b へ収束。
- **「つなぎ（CI3.1.13+PHP8.1）」を先に当てて当座のサポート切れを即解消**しつつ、本移行を落ち着いて進める二段構えが安全。
- res-sys は **別サーバーで独立起動を維持**（モノレポにしない）。共有は Composer パッケージ越しに read-only で行う。
