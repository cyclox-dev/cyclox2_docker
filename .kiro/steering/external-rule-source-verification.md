# 外部情報源（規則ページ等）の検証ポリシー

## 対象

AJOCC公式ルールページ（https://www.cyclocross.jp/about/rules-regulations.html）など、
本プロジェクトの昇格・残留・降格・配点ルールの一次情報源となる**外部Webページ**を
実装やspecの確定値として参照する場合すべてに適用する。

## 背景（このルールができた理由）

`season-rules-2026-27` タスク1（2026-08-29実装）で、AJOCC公式ページの昇格人数
テーブルの数値を誤って読み取り、誤った確定値をコード・agreement-log.mdに記録した。
もみじシクロクロス第2戦（2026-09-23）で実際に誤算出が発生し、主催者からの問い合わせ
（2026-09-24）で発覚した。

原因は、当該テーブルが `rowspan` でセルを結合した構造だったこと：

```html
<tr><td>10～19名</td><td rowspan="2">1名</td><td>1名</td></tr>
<tr><td>20～29名</td>                        <td>2名</td></tr>
```

2行目（20〜29名）には本来「MM2→MM1」列のセルが存在しない（1行目のrowspanが
覆っている）。rowspanを考慮しない単純なHTML読み取り（AI要約付きのWebFetch等を含む）
だと、隣接列の値が誤って対象列の値として読まれる「列ズレ」が起きる。この誤読は
**独立レビューでも検出されなかった**（レビュアーも同じ経路の情報を参照したため）。

詳細な経緯: `.kiro/specs/season-rules-2026-27/agreement-log.md`
（「2026-09-24 タスク1の昇格人数区分に誤り発覚・訂正」節以降）

## ルール

1. **外部ページの表形式データを確定値として採用する前に、必ず生HTMLを取得して
   `rowspan`/`colspan`属性を目視確認する。**
   ```bash
   curl -s -A "Mozilla/5.0" <URL> -o /tmp/rules.html
   grep -n -A3 "<table" /tmp/rules.html  # 該当テーブルを特定してから rowspan/colspan を確認
   ```
   WebFetch等のAI要約ツール単体の結果は、`rowspan`/`colspan`の構造を保持しない
   ことがあるため、**確定値の根拠としては使わない**（一次スクリーニング・当たりを
   つける用途に留める）。

2. **既存コードの別カテゴリー用配列・定数と数値が一致しても、それを「答え合わせが
   取れた」と解釈して検証を緩めない。** むしろ独立した規則制定側の数値が既存実装の
   定数とたまたま一致するのは偶然の可能性と誤読の可能性の両方があるため、
   追加の確認材料であって代替にはならない。

3. **独立レビュー（reviewer等）を行う場合も、先行工程の要約や記録を鵜呑みにせず、
   生HTMLへ遡って独自に再確認すること。** 二次資料同士の突き合わせだけでは、
   同じ誤読が継承され検出できない。

4. **確定値を記録する際は、根拠（生HTML取得方法・確認した`rowspan`/`colspan`構造）
   を一次成果物（design.md・agreement-log.md等）に残す。** 「公式ページと照合済み」
   とだけ書くのではなく、どう確認したかを記録する。

## 適用範囲外

- 表形式でない自由記述のルール文（例:「複数カテゴリー合算開催では上位カテゴリーと
  同条件の昇格基準となる」等）はrowspanの問題が起きないため対象外。ただし、こうした
  記述が指す先のテーブル（例:「MM3→MM2の出走人数基準を適用する」）を特定する際は
  上記ルールが適用される。
