# 昇格の誤付与を是正する運用手順

## 対象

リザルトに基づく昇格（`category_racers.reason_id = RESULT_UP`）が誤って付与された場合の
是正手順。誤付与の原因は問わない（昇格人数ルールの実装誤り、リザルトの順位訂正、
出走人数の変更など）。カテゴリーや系統には依存しない。

## 押さえるべき仕組み

1. **リザルト再計算は昇格を取り消さない。** 再計算（管理画面の再計算、リザルト取込、
   API経由のアップロード）は、今回の昇格枠に入った選手にだけ昇格を付け直す。枠から
   外れた選手の既存の昇格行は処理対象にならず、そのまま残る。ルールや順位を修正した後に
   再計算しても、誤った昇格は消えない。
2. **ressysの昇格者欄は昇格行の有無だけで決まる。** `reason_id = RESULT_UP` かつ
   `deleted = 0` の行を、そのリザルト（`racer_result_id`）に紐づけて表示する。
   `cancel_date` は見ないため、終了日を入れる方法では欄から消えない。
3. **昇格は複数の行にまたがる。** 昇格先の行に加えて、昇格元の行の終了日（`cancel_date`）、
   系統間連動で付与された相手系統の行が関係する。

## 手順

1. **本番にコード修正が反映済みか確認する。** 旧コードのままだと、再計算のたびに誤った
   昇格が付け直される。反映前に是正しても意味がない。ログ（`app/tmp/logs`）の
   `rank up count:N` で、その大会の昇格枠数が期待どおりかを確認できる。
2. **対象の行を特定する。** 選手コードと大会コードで、`RESULT_UP` の昇格行、その昇格元の行、
   連動で付与された行を洗い出す。連動側は元のカテゴリーを本番で確認してから戻す。
   推測で戻さない。
   ```sql
   SELECT id, category_code, apply_date, cancel_date, reason_id, meet_code, racer_result_id, deleted, created
   FROM category_racers WHERE racer_code = '<選手コード>' ORDER BY id DESC LIMIT 20;
   ```
3. **昇格行を論理削除する**（`deleted = 1`）。ressysの昇格者欄はこれで消える。
4. **昇格元の行の `cancel_date` を、昇格前の状態に戻す。**
5. **連動で付与された相手系統の行を、昇格前の状態に戻す**（付与行の論理削除と、終了させた行の
   `cancel_date` 解除）。
6. **再計算せずに確認する。** 選手のカテゴリー所属と、ressysの昇格者欄が期待どおりかを見る。
   是正後の再計算は、誤った昇格を付け直さないことが確認できてからにする。

## 是正後の注意

- 同じレースのリザルトを保存し直すと再計算が走る。ルール修正が本番に反映されるまでは、
  該当レースのリザルトを触らない。
- 是正の内容（対象選手、戻した行、日時）は、そのタスクの `agreement-log.md` に記録する。

## 補足（設計上の位置づけ）

再計算で昇格を取り消す実装にはしていない。取消は連動更新、残留ポイント、手動編集との
整合に影響するため、是正は上記の手動手順で行う方針とした（2026-09-25、ユーザー判断）。
