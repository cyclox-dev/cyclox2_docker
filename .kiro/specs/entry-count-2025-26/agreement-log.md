## 壁打ち概要

過去のシクロクロス大会のシーズンごとエントリー数・出走数を集計した参照ファイル
`tmp/20250416_entry_racers.xlsx` を基に、**2025-26シーズン**の集計を行う。

- 出力形式: 参照ファイルの「通しでカウント」シートに 25-26 シーズン行を追加した形。
- データソース: ローカルで動作する Docker MySQL（`cyclox2_mysql` コンテナ / `cyclox2` DB）。
- 過去集計（24-25）をローカルDBで再現し、計算が一致するか検算する。

### 集計ロジックの出所
参照ファイル `sql` シートに記載された MySQL クエリを踏襲。期間条件のみ 25-26 用に変更。

---

## 集計定義（参照SQLを踏襲）

- **対象期間**: `meets.at_date > 'YYYY-04-01' AND at_date < 'YYYY+1-04-01'`
  - 25-26 は `2025-04-01` 〜 `2026-04-01`
- **entry数**: `entry_racers` を `entry_categories`/`entry_groups`/`meets`/`racers` に内部結合し、
  全テーブル `deleted=0`、`er.entry_status=0` の行数。
- **started数**: 上記に `racer_results`（`rr.status != 0 AND rr.deleted=0`）を内部結合した行数。

### コード定義による裏付け
- `racer_results.status`（[RacerResultStatus.php](../../../cyclox2_svr/cyclox2/app/Cyclox/Const/RacerResultStatus.php)）:
  `0=DNS(出走せず)` / `1=FIN` / `2=DNF` / `3=DSQ` / `4=LapOut` / `5=80%Out`。
  → `status != 0` は **DNS を除く全員＝実際に出走した人** であり「出走数(started)」の意図と厳密に一致。
- `entry_status`（[RacerEntryStatus.php](../../../cyclox2_svr/cyclox2/app/Cyclox/Const/RacerEntryStatus.php)）:
  `0=Normal` / `1=オープン`。→ `entry_status=0` は **Normal エントリーのみ**（オープン参加は対象外）。

## 検証: SQLが作業意図を正確に反映しているかの確認

実装前に、参照SQLが「entry数＝有効エントリー」「started数＝実出走」という意図を正しく表現しているか、
コード定義と 25-26 実データの両面から検証した（詳細値は `test-results.md`）。

| 観点 | SQLの扱い | 25-26 実データ | 判定 |
|---|---|---|---|
| entry数 = `entry_status=0` | Normalのみ（オープン除外） | Normal 21,604 / オープン 22 を除外 | 意図反映（決定#3で確定） |
| started数 = `status != 0` | DNS以外＝出走者 | DNS 2,508 を除外、出走 18,802 | status定義と完全一致 |
| `inner join racers AND racers.deleted=0` | 削除/未登録選手を除外 | 除外 0 件 | 25-26は影響なし |
| started 二重カウント | 1エントリー=1結果前提 | 複数結果を持つエントリー 0 件 | 重複なし |
| 期間境界（strict 不等号） | 04-01ちょうどを除外 | 境界日の大会 0 件 | 影響なし |
| データ確定度 | 結果未入力は非出走扱い | 現在2026-06でシーズン終了済 | 確定済 |

> 参照ファイル `sql` シートには「`racers.deleted` 行で数が変わる（@20-21 で削除済み選手 26 件による不一致）」という
> メソッド固有の弱点メモがあるが、**25-26 では該当 0 件**のため数値に影響しない（24-25 を完全一致で再現できたことが裏付け）。
