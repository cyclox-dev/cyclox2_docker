## 1. ポイントシリーズの登録

管理画面: ポイントシリーズグループ「東北」→ シリーズ追加（`PointSeries/add`）

**主催者が確定したカテゴリーごとに1シリーズを登録する。** シリーズ本数・カテゴリー構成は
大会運営の中で決定される事項であり、本 runbook では固定しない。

### 設定値（全シリーズ共通）

| 項目 | 値 | 備考 |
|---|---|---|
| ポイントシリーズグループ | 東北 | 開発環境では `point_series_group_id=2` |
| シーズン | 2026-27 | 開発環境では `season_id=17` |
| 配点ルール（`calc_rule`） | **`TCX_267`（=14）** | ここが前シーズンからの唯一の変更点 |
| 集計ルール（`sum_up_rule`） | **2**（全戦合計のみ） | 2017-18 以降変更なし |
| 有効期間ルール（`point_term_rule`） | **1**（無期限有効） | 2017-18 以降変更なし |
| 付与対象（`point_to`） | **1**（選手へ付与） | 画面上は hidden 固定。入力不要 |

> 前シーズン（25-26）は `calc_rule=12`（`TCX_245`）。**26-27 は必ず `TCX_267`（=14）を選ぶこと。**
> 選択を誤ると 24-25 の旧配点で集計される。

### 命名規則

| 項目 | 形式 | 例 |
|---|---|---|
| シリーズタイトル（`name`） | `東北シクロクロス26-27{カテゴリー}` | `東北シクロクロス26-27ME1` |
| 短縮タイトル（`short_name`） | `TCX26-27{カテゴリー}` | `TCX26-27ME1` |

> 25-26 のデータには短縮タイトルの先頭に空白が混入した行（`" TCX25-26ME2"`）がある。
> 前後に空白が入らないよう注意すること。

### 公開設定（`publishes_on_ressys` / `publishes_newest_asap`）

25-26 実績では、上位カテゴリー6本を公開、残りを非公開としていた。**参考情報**であり、
26-27 の公開方針は主催者判断で決めること。

| 公開（両フラグ=1） | 非公開（両フラグ=0） |
|---|---|
| ME1 / WE1 / MM1 / CK1 / CK2 / CK3 | ME2 / ME3 / ME4 / WE2 / MM2 / MM3 |

`public_psrset_group_id` は公開処理が自動採番するため、通常この画面で入力する必要はない。
`hint` は 25-26 の東北シリーズ12本すべてで空欄。特段の理由がなければ空欄のままにすること。

> **やってはいけないこと**: 既存の 25-26 シリーズの `calc_rule` を 14 に変更しないこと。
> 集計（`calcUpSeries`）は既存の `point_series_racers` を読むだけなので変更直後は何も起きないが、
> 後日そのシーズンのリザルト再計算が走った時点で 25-26 のランキングが 26-27 の配点で
> 上書きされ、壊れる。**26-27 のシリーズは新規に作成すること。**

### 参考: 25-26 のシリーズ構成（12本）

`ME1` / `WE1` / `MM1` / `CK1` / `CK2` / `CK3` / `ME2` / `ME3` / `ME4` / `WE2` / `MM2` / `MM3`

> 26-27 は AJOCC 規則改正（ME⇔MM連動など）があるため、この構成のままとは限らない。
> **主催者が確定した構成に合わせること。**

## 2. 大会の紐付け（`meet_point_series`）

各シリーズに、対象となる大会×エントリーカテゴリーを紐付ける。

### 必須項目

| 項目 | 備考 |
|---|---|
| `express_in_series` | **NOT NULL**。シリーズ内での表示名。25-26 実績は `#1亘理` の形式（`#{戦番号}{会場名}`） |
| `meet_code` | 対象大会のコード |
| `entry_category_name` | 対象エントリーカテゴリー名 |

参考: 25-26 の東北シリーズは各シリーズ5大会（`MM1` のみ3大会）が紐付いていた。

---

## 3. 作業順序の制約（重要）

**紐付けは、対象大会のリザルト登録より前（シーズン開幕前）に完了させること。**

理由: シリーズ点の付与と集計は2段階に分かれている。

1. **付与**: リザルト登録・編集時に `ResultParamCalcComponent::__resetSeriesPoints()` が
   `PointCalculator` を呼び、`point_series_racers` に行を作成する
2. **集計**: `calcUpSeries` は既存の `point_series_racers` を読んで順位を出すだけで、
   `PointCalculator` を呼ばない

したがって、**リザルト登録済みの大会に後からシリーズを紐付けても、`point_series_racers` は
生成されず、シリーズランキングは空のままになる**。

### 既にリザルトがある大会へ後から紐付けた場合

- [ ] 対象エントリーカテゴリーの**リザルト再計算（`reCalcResults`）を実行する**
- [ ] 再計算後に `point_series_racers` に行が作成されていることを確認する
- [ ] `calcUpSeries` でランキングが表示されることを確認する

参考: 25-26 の `meet_point_series` はシーズン開幕前（2025-08-12）に作成されており、
実運用は「先に紐付け → リザルト登録」の順序である。

## 補足: ロールバック時の注意

> **前提（2026-08-16 更新）**: ロールバック安全化の2件が**本番へ先行リリース済み**である。
> - cyclox2web PR #17: `PointSeries/view.ctp` / `PointSeriesGroups/view.ctp` の null 安全化。
>   未登録 `calc_rule` は「(不明 #N)」と表示され、fatal にならない。あわせて
>   `EntryCategoriesController` の Notice（論理削除シリーズ参照時）も解消
> - cyclox2web PR #18: `__resetSeriesPoints()` の `if (empty($calc)) return;` を
>   `continue`（＋ERRORログ＋`RET_FAILED`）へ変更。未登録の配点ルールは**当該シリーズのみ
>   スキップ**され、他シリーズのポイントは再作成される
>
> これにより、以前このセクションに記載していた「画面の fatal」と「他シリーズのポイント消失」は
> **いずれも解消済み**である。

`calc_rule=14` の `point_series` 行が存在する状態でアプリを `TCX_267` 未反映の版へ
ロールバックした場合、残る影響は次の1点のみ。

### 残る影響: 当該シリーズ自身のポイントが再作成されない

リザルト再計算（`reCalcResults` → `__resetSeriesPoints()`）は、冒頭で対象リザルトの
全シリーズポイントを `deleteAll()` してから各シリーズを再計算する。`TCX_267` 未反映の版では
`getCalculator(14)` が `null` を返すため、**`calc_rule=14` のシリーズのポイントだけは
削除されたまま再作成されない**（他シリーズは PR #18 により正常に再作成される）。

このとき `error.log` に次の形式で記録されるため、事後の検知は可能。

```
Error: 選手<racer_code>(racer_result_id:<id>) のポイントシリーズ<シリーズ名>の配点ルール(14)が
コード上に未登録です。このシリーズの既存ポイントは削除されたまま再作成されません。
```

### ロールバック手順

- [ ] **`calc_rule=14` の `point_series` を削除する**（物理削除、または `meet_point_series` の
      紐付け削除で再計算経路から外す）
- [ ] ロールバック後に当該大会のリザルト再計算を行った場合は、`error.log` に上記のエラーが
      出ていないか確認する
- [ ] 再リリース時は、`calc_rule=14` のシリーズを再登録し、対象カテゴリーのリザルト再計算を
      実行してポイントを復元する
- [ ] 上記を関係者へ周知してからアプリを戻す
