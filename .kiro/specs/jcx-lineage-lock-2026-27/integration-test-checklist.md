- [ ] JCX大会へ、既にシーズン内で系統（エリート/マスターズ）が固定済みの選手を、**逆の系統**で
  新規エントリー登録する。警告（固定系統・根拠大会名/開催日・違反系統・回避策）が表示され、
  保存は行われないことを確認する（Requirement 3.1, 3.4）。
- [ ] 上記の警告画面で確認チェックボックスにチェックを入れて再送信し、登録が完了することを
  確認する（Requirement 5.2）。
- [ ] 上記のオーバーライド実行後、`app/tmp/logs/jcx_lineage_lock.log` に実行者（ログインユーザー）・
  選手・大会・違反内容・日時が記録されていることを確認する（Requirement 5.3）。
- [ ] エントリーの所属先（`entry_category_id`）を編集で変更し、変更後の系統が固定系統と異なる
  場合も同様に警告→確認付き再送信のフローが働くことを確認する（Requirement 3.2）。
- [ ] 非JCX大会へのエントリー登録・編集では、警告が一切表示されず従来どおりの挙動であることを
  確認する（Requirement 7.1）。

### 種目変更（`EntryCategoriesController::edit`）

  ことを確認する（Requirement 3.3, 3.4）。
- [ ] 確認付き再送信で種目変更が完了し、ログに記録されることを確認する（Requirement 5.2, 5.3）。

### 運用モード切替（`mode`: `warn` → `block`）

- [ ] `app/Config/bootstrap.php` の `Configure::write('JcxLineageLock.mode', ...)` を
  一時的に `'block'` に変更し、コンテナを再起動する。
- [ ] block モードで系統違反となる登録・編集を試み、確認チェックボックス等のオーバーライドUIが

- [ ] 確認後、`mode` を `'warn'`（既定・確定済み）へ戻し、コンテナを再起動して復元する。

  `jcx_lock_override` を送っていなくても処理が完了することを確認する（Requirement 5.5、
  cyclox2app は `jcx_lock_override` を送信しない前提）。
- [ ] 上記の登録後、`app/tmp/logs/jcx_lineage_lock.log` に「経路:API登録（自動受理）」として

- [ ] 同一大会（同じ `meet_code`）のエントリーデータを再アップロードし、自大会の既存エントリーが

- [ ] block モードに切り替えた状態で同様の違反データを送信し、登録が拒否され

  （Requirement 5.4）。
- [ ] **既存の `add_entry` 成功応答の型・フィールド構成が本改修前と一切変わっていない**ことを、
