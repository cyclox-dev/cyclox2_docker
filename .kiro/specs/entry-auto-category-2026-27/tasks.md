# Implementation Plan

- [ ] 1. 基盤整備: 資格年齢判定と種目解決の共通ロジック
- [ ] 1.1 資格年齢判定ロジックの実装（TDD）
  - 選手が指定カテゴリーの資格年齢要件（`categories.age_min`）を指定日時点で満たすかを判定する
    共通ロジックを実装する。年齢計算は既存の年齢計算ロジック（大会開催日基準）を再利用する
  - 誕生日当日・前日・翌日の境界値テストケースを含む
  - C1〜C4（19/17/15/13歳）・CM1〜CM4（35歳）のいずれのカテゴリーでも正しく判定できることを
    単体テストで確認する（観測可能な完了条件: 全境界値パターンでテストがgreen）
  - _Requirements: 3.1, 8.1, 9.1_
  - _Boundary: CategoryLineageLinker_

- [ ] 1.2 種目の単一カテゴリー対応判定の実装（TDD）
  - エントリー先の種目（`races_category_code`）が対応表管理対象の実力別カテゴリー1つに一意
    対応するかを判定するロジックを実装する。プール種目（複数対応）・対応表対象外カテゴリーは
    非対応として扱う
  - 単一対応（例: C4種目）・プール種目（例: C3+4種目）・対応表対象外の3パターンで単体テストが
    greenになることを観測可能な完了条件とする
  - _Requirements: 1.1, 2.3, 4.1_
  - _Boundary: CategoryLineageLinker_
  - _Depends: 1.1_

- [ ] 2. Core: エントリー時の対応ペア補完
- [ ] 2.1 対応ペアのオンデマンド補完ロジックの実装（TDD）
  - 既存の連動先解決・保有確認ロジックと、1.1の資格年齢判定・1.2の種目解決を組み合わせ、選手が
    相手系統のカテゴリーを1件も有効保有していない場合にのみ、対応表に基づく対応ペアを新規付与する
    ロジックを実装する。既存の有効カテゴリーは対応ペアが正しいか不整合かを問わず一切cancelしない
  - 資格年齢要件を満たさない場合は見送りとして扱い、見送り理由を後続処理が取得できる形で返す
  - 正常付与、相手系統既保有（正しいペア/対応外ペア/重複保有の3パターン）でのスキップ、
    資格年齢未達でのスキップ、元ME1特例経由でのC1付与のいずれも単体テストがgreenになることを
    観測可能な完了条件とする
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 3.2, 4.2, 7.1_
  - _Boundary: CategoryLineageLinker_
  - _Depends: 1.1, 1.2_

- [ ] 3. Core: エントリー保存フックとの統合
- [ ] 3.1 エントリーモデルへの補完トリガーの実装（TDD）
  - エントリーの新規登録、またはエントリー先カテゴリーの変更を伴う更新の場合にのみ、保存成功後に
    2.1の補完ロジックを呼び出すトリガーを実装する。無関係なフィールドの更新では発火しない
  - 補完処理中の例外は捕捉してログに記録し、保存結果には一切影響させない
  - 見送りが発生した場合、その内容を後続の呼び出し元が取得できる形で蓄積する
  - 新規登録での補完発火、エントリー先変更を伴う更新での再判定、無関係フィールド更新での非発火、
    保存自体が失敗した場合の非発火のいずれも単体/統合テストで確認できることを観測可能な完了
    条件とする
  - _Requirements: 5.1, 5.2, 5.3, 6.1, 6.2, 6.3_
  - _Boundary: EntryRacer_
  - _Depends: 2.1_

- [ ] 4. Integration: エントリー経路での警告配信
- [ ] 4.1 (P) 管理画面・個別API経路での警告配信
  - 管理画面での個別登録・編集が成功した際、見送りが発生していれば操作者に内容が分かる形で
    画面上に提示する。個別APIでの登録が成功した際は、応答に見送り内容を含む警告情報を追加する
  - 資格年齢未達等で見送りが発生したエントリー登録で、画面にメッセージが表示される、または
    API応答に警告フィールドが含まれることをテストで確認できることを観測可能な完了条件とする
  - _Requirements: 6.4, 6.6_
  - _Boundary: EntryRacersController_
  - _Depends: 3.1_

- [ ] 4.2 (P) 一括API登録経路での警告配信
  - 一括エントリー登録の成功応答に、保存された各エントリーから蓄積された見送り内容を集約して
    含める。既存の成功/失敗判定フォーマット自体は変更しない
  - 一括登録の中に見送りが発生したエントリーが含まれる場合、成功応答に警告情報が含まれることを
    テストで確認できることを観測可能な完了条件とする
  - _Requirements: 6.5, 6.6_
  - _Boundary: ApiController_
  - _Depends: 3.1_

- [ ] 5. Core: 昇格連動・是正バッチへの資格年齢ガード適用
- [ ] 5.1 (P) 昇格連動への資格年齢ガード挿入（TDD）
  - レース結果による昇格連動が、相手系統へカテゴリーを新規付与しようとする直前に、1.1の資格年齢
    判定を挿入する。資格年齢を満たさない場合は新規付与（cancel・create）を一切行わず、その旨を
    示す結果を返す。既存の戻り値の型・他の判定分岐（連動不要判定等）は変更しない
  - 相手系統が空かつ資格年齢未達で新規付与が行われないこと、相手系統に既に何か保有している
    場合（＝既に資格年齢を満たす）の従来動作が維持されること（回帰）を単体テストで確認できる
    ことを観測可能な完了条件とする
  - _Requirements: 8.1, 8.4_
  - _Boundary: CategoryLineageLinker_
  - _Depends: 1.1_

- [ ] 5.2 (P) 是正バッチへの資格年齢ガード挿入（TDD）
  - 既存不整合データの是正バッチが対応カテゴリーを新規付与しようとする直前に、1.1の資格年齢
    判定を挿入する。資格年齢を満たさない場合は当該選手への新規付与のみをスキップし、正系統の
    維持や不整合カテゴリーの終了処理はそのまま実行する。見送った選手を是正結果レポート上で
    明示する
  - バッチの実行そのもの（他選手の是正処理を含む）は資格年齢の確認を理由に中断・失敗させない
  - 資格年齢未達選手を含む複数選手の是正実行で、当該選手は新規付与のみスキップされレポートに
    明示される一方、他選手の是正・バッチ全体の正常終了には影響しないことを単体/統合テストで
    確認できることを観測可能な完了条件とする
  - _Requirements: 9.1, 9.2, 9.3, 9.4_
  - _Boundary: CatRacerCleanupShell_
  - _Depends: 1.1_

- [ ] 6. Integration: 昇格連動の見送り記録
- [ ] 6.1 昇格連動呼び出し元でのログ記録統合
  - 昇格連動の呼び出し元（2箇所）に、5.1で新設した資格年齢見送りの結果を検知してログに記録する
    分岐を、既存の失敗時ログ記録と同じ形式で追加する
  - リザルト取込で昇格が発生し対象選手が資格年齢未達の場合、リザルト取込処理自体は成功し、
    見送りがログに記録されることを統合テストで確認できることを観測可能な完了条件とする
  - _Requirements: 8.2, 8.3_
  - _Boundary: ResultParamCalcComponent_
  - _Depends: 5.1_

- [ ] 7. Validation: 統合・境界確認
- [ ] 7.1 エントリー全経路での統合テスト
  - 管理画面での個別登録・編集、個別API登録、一括API登録（内部的なカスケード保存を含む）の
    全経路で、対応ペア補完が同一基準で発火することを確認する
  - 同一の入力条件（新規エントリー・資格年齢未達エントリー）に対し、経路によらず同一の補完結果・
    見送り結果が得られることをテストで確認できることを観測可能な完了条件とする
  - _Requirements: 5.1_
  - _Depends: 3.1, 4.1, 4.2_

- [ ] 7.2 E2Eシナリオと適用対象範囲の境界確認
  - 発端事例（片方の系統のみ保有する選手が相手系統の種目へ新規エントリーする）を模した登録で
    対応ペアが自動補完される正常系シナリオ、資格年齢未達選手のエントリー登録で見送りが提示される
    シナリオ、リザルトアップロードでの昇格に伴う資格年齢見送りシナリオ、是正バッチ実行での
    資格年齢見送りシナリオを確認する
  - 新規選手登録時のカテゴリー指定・系統切替画面（change_em相当）の既存の経路・既存テストに
    変化がないこと（本ガードが適用されないこと）を確認する
  - 既存の資格年齢要件違反データに対して本ガードが遡及的な変更を一切行わないことを確認する
  - 上記いずれのシナリオも実行結果が期待どおりであることをテストで確認できることを観測可能な
    完了条件とする
  - _Requirements: 1.1, 6.4, 8.2, 9.2, 10.1, 10.2, 10.3, 10.4_
  - _Depends: 7.1, 6.1, 5.2_
