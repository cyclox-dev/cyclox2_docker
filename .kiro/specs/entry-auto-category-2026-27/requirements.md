# Requirements Document

## Project Description (Input)

AJOCC 2026-27規則改正により、実力別エリート（ME1〜ME4=categories.code C1〜C4）と実力別マスターズ
（MM1〜MM3=CM1〜CM3）は対応ペアを両保有するのが正常状態になった（me-mm-linkage-2026-27で実装済み・
クローズ済み）。ただし現状、対応ペアの自動連動は「レース結果による昇格」時にしか発火しない
（`CategoryLineageLinker::propagateLinkedPromotion()`）。片方の系統のみを保有する選手が、レース前に
相手系統でエントリーしただけでは何も起きず、主催者が「エントリー後・レース開催前」に手動で相手側
カテゴリーを付与する運用が前提になっている。関西シリーズのように同一選手が年間10戦以上・シーズン中
ずっと系統を行き来する運用では、この手動付与が主催者の恒常的な負荷になっている（発端: CCM-000-0487
上田尚徳選手が開幕・桂川にMM3でエントリーした際の事例）。

対応案として「既存の単独保有者（約11,210名）全員に対応ペアを一括でバッチ付与する」案と「エントリー
登録という実際の行動をトリガーに、その選手だけ対応ペアをオンデマンドで補完付与する」案を比較検討
した（判断ブリーフ: https://claude.ai/code/artifact/1f6a3a64-e59d-4a67-ae43-837b96e544c4 に実データ
分析・実現性検証を記録済み、人間承認済み）。一括付与は年齢資格チェックの欠如・ME1連鎖降格・既存
不整合データ(406名)との干渉などのリスクが大きいため不採用とし、エントリー時オンデマンド付与を
主策として採用する。

エントリー保存の全経路（管理画面・外部API一括登録・リザルト取込によるエントリー再作成）が必ず
通過する`EntryRacer`モデルの保存フック（`beforeSave`/`afterSave`。jcx-lineage-lock-2026-27がJCX
系統固定チェックで同じ場所に実装済みの実績パターン）に、対応ペア補完ロジックを追加する。エントリー
先の`races_category_code`が単一カテゴリー（C1〜C4/CM1〜CM3のいずれか一意）に対応し、かつ選手が
相手系統の有効カテゴリーを1件も保有していない場合にのみ、`CategoryLineageMap`の対応表に基づいて
相手側カテゴリーを新規付与する。既存カテゴリーの`cancel`は一切行わない（`propagateLinkedPromotion()`
とは異なる、supplement専用の新ロジックとして実装する）。年齢資格チェック（既存の
`__isProperAgeForCat()`相当）を新たに設けることが前提。

残る主要な設計論点:
1. プール種目（C3+4・CM2+3・CM1+2+3。2025-26シーズンの全エントリーの1.8%）はエントリー時点で系統が
   一意に決まらないため、エントリー時点では対象外とするか、リザルト取込時の`as_category`解決結果を
   使ったフォールバック処理を別途設けるかを要件定義で確定する。
2. 元ME1判定など既存の`CategoryLineageLinker::resolveLinkedTarget()`の特例ロジックをそのまま流用
   する前提。
3. 一括付与（案A）は不採用とするが、直近出走実績のある選手に限定した小規模backfillを別途・任意で
   検討する余地は残す（本specのスコープには含めない）。

このspecは`me-mm-linkage-2026-27`（クローズ済み・再オープンしない）が定義する`CategoryLineageMap`
を単一の正として参照し、対応表の重複定義は行わない。公開インターフェース（保存時の自動カテゴリー
付与という新しい挙動）の追加にあたるため、実装時はTier 2（テスター→レビュアーの順で検証）を
既定とする。
