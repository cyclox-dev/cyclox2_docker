# Implementation Plan

- [x] 1. Foundation: 欠陥を再現する回帰テストの土台
- [x] 1.1 反復取込の再現テストを先に追加する（TDD）
  - 同一の昇格連動を3回連続で実行するテストを、連動処理の単体テストへ追加する。**各回で昇格元
    リザルトの識別子を変える**（実運用の再取込ではリザルト行が毎回作り直され識別子が変わるため、
    固定すると本番障害を再現できない）
  - 相手系統の有効保有がちょうど1件であることを期待値とする
  - **観測可能な完了条件**: 修正前の現行コードでこのテストが失敗し、失敗内容が「有効保有が3件」
    であることを実行結果で確認できる（ミューテーション確認）
  - _Requirements: 1.1, 1.2_

- [x] 2. Core: 連動処理の冪等化
- [x] 2.1 相手系統の保有判定から日付窓を外す
  - 連動先の保有判定が、有効開始日が大会開催日より後の行も有効として扱うようにする
  - 保有している行が連動先と一致する場合は、新規作成も終了処理も行わない
  - 保有している行が連動先とは異なり、かつその有効開始日が大会開催日より後の場合は、終了日が
    有効開始日より前になる矛盾を避けるため、終了処理も新規作成も行わずに見送る。この見送りを
    表す結果種別を新設する
  - ソフト削除済みの行は判定対象に含めない
  - **観測可能な完了条件**: 未来日の有効開始日を持つ行を用意した単体テストで、一致時は何も
    起きず、不一致時は新設した見送り結果が返り、DBが変化しないことを確認できる
  - _Requirements: 1.3, 1.4, 2.1, 2.2, 2.3, 2.4_

- [x] 2.2 当該取込に由来する連動先行の後始末を追加する
  - 連動先を解決した直後・保有判定の前に、当該取込が過去に自ら作成した連動先行を取り除く
  - 対象の特定条件は昇格元系統側の冪等化削除と同じ構成とし、**取込のたびに変わる識別子は
    条件に含めない**
  - 手動付与・エントリー補完・他大会の昇格に由来する行が対象に入らないことを、対象特定条件で
    保証する
  - 後始末は資格年齢の確認より前に実行されるため、資格年齢を満たさなくなった選手では「行を
    取り除いたうえで新規作成しない」結果になる。これは意図した挙動であり、前回の取込時点では
    資格を満たしていた選手の生年月日が訂正された場合にのみ起きる。この判断をコード上の説明として
    残す
  - **観測可能な完了条件**: 1.1 のテストが green になり、かつ同一選手に手動付与行・他大会由来の
    連動行を同居させたテストで、それらが削除されずに残ることを確認できる
  - _Requirements: 1.1, 1.2, 3.1, 3.2, 3.3_

- [x] 2.3 連動処理の内部判断をログに記録する
  - 後始末を実行した場合、既に連動先を保有していて新規作成しない場合、未来日の別カテゴリー
    保有により見送った場合の3つを、それぞれ設計で定めた水準で記録する
  - 記録には選手・大会・連動先を含め、事後に対象を特定できる形式とする
  - **観測可能な完了条件**: 各分岐を通すテストの実行後、ログファイルに該当行が出力されている
    ことを確認できる
  - _Requirements: 6.1, 6.2, 6.3_

- [x] 3. Integration: 呼び出し元への結果種別の反映
- [x] 3.1 昇格処理の2つの呼び出し箇所へ新結果種別の記録分岐を追加する
  - 資格年齢未達の見送りを記録している既存分岐と同じ形で、新設した見送り結果を記録する分岐を
    追加する。昇格判定・呼び出し順序・引数は変更しない
  - 見送りが発生しても昇格処理そのものは従来どおり継続する
  - **観測可能な完了条件**: 見送りが発生する条件を作った統合テストで、昇格自体は成功し、
    ログに見送りが記録されることを確認できる

## Implementation Notes

- **1.1 を必ず最初に行う。** 修正後にテストを書くと「毎回異なるリザルト識別子を与える」という
  再現の要点を取りこぼしても気づけない。修正前に失敗することを確認してから 2.x に進む。
- **2.1 と 2.2 は同一メソッドを編集するため並行不可。** 2.1（判定の是正）→ 2.2（後始末の追加）の
  順に行う。後始末は保有判定より前に挿入する（設計の Key Decisions 参照）。
- **資格年齢の確認位置は動かさない。** 保有判定の後という現行の位置を維持する。前へ動かすと
  既に正しいペアを保有している資格年齢未達の選手の結果種別が変わり、5.2 に反する。
- **5.1 と 6.1 はコードに触れないため、2.x〜4.x と並行して進めてよい。** ただし 5.2 は
  4.3（回帰確認）とデプロイの完了を待つ。
- テストの実行は `docker exec cyclox2_svr bash -c "cd /var/www/html/app && Console/cake test app <path>"`。
  コンテナは main チェックアウトをバインドマウントしている点に注意する。
- 実装は Tier 2 で進める（実装 → tester → reviewer の順に検証を委譲）。
