# 系統間連動の多重付与 — 既存データ是正の手順

spec: `lineage-propagation-idempotency-2026-27` / タスク5.1・5.2（Requirement 4）

## この是正が対象とするもの

リザルトの再取込のたびに増えていた、系統間連動由来（`reason_id = 12`）のカテゴリー所属の
余剰行。**同一の（選手・カテゴリー・有効開始日・大会）に最新の取込に対応する行が別に残って
いるものだけ**を対象とし、最新の1件は必ず残す。

開発DB（本番相当）での検出結果は5選手・8行。

| 選手 | カテゴリー | 有効開始日 | 大会 | 余剰行 |
|---|---|---|---|---|
| MMJ-234-3001 | C2 | 2026-09-24 | MMJ-267-002 | 4 |
| CHB-178-0029 | CM1 | 2026-09-23 | CXK-267-002 | 1 |
| KNS-167-0340 | C2 | 2026-09-23 | MMJ-267-001 | 1 |
| KNS-245-0133 | C2 | 2026-09-23 | MMJ-267-001 | 1 |
| TYM-190-0004 | CM2 | 2026-09-23 | CXK-267-002 | 1 |

本番の件数はその後の取込により異なりうるため、**必ず `01` の出力を人間が確認してから適用する**。

## 対象にしないもの

- 昇格そのものの行（`reason_id = 2`）、手動付与、エントリー補完による付与
- 重複していない単独の連動行
- 本欠陥に起因しない既存の不整合（対応外ペア・同系統内複数保有・古い重複）。これらは
  `catracer-cleanup-2026-27` の管轄

`reason_id = 12` を条件に含めるため、本欠陥の稼働開始（2026-09）より前の行は構造的に対象外に
なる（開発DBで `reason_id = 12 かつ apply_date < 2026-01-01` は0件であることを確認済み）。

## 実行順序

**前提: 本specのコード修正が本番へ適用済みであること。** 適用前に是正しても、次の再取込で
同じ重複が再発する（実例: `KNS-000-2879` は2026-09-24 07:31〜07:32に運営者が4行を手動削除したが、
約5分後 07:37:31 の取込で再び1行作られた）。

| # | ファイル | 内容 | 副作用 |
|---|---|---|---|
| 1 | `01_detect_duplicates.sql` | 是正対象の一覧と選手ごとの要約を出力 | なし（読み取りのみ） |
| 2 | — | **出力を人間が確認し、承認を得る** | — |
| 3 | `02_backup.sql` | `category_racers` 全体をバックアップ表へ複写 | バックアップ表を1つ作成 |
| 4 | `03_fix_duplicates.sql` | 対象 id を作業表へ確定 → 対象行を `deleted = 1` へ更新 | 作業表を1つ作成、対象行をソフト削除 |
| 5 | `04_verify.sql` | 是正後の3項目を検証 | なし（読み取りのみ） |
| 6 | — | `CatRacerCleanupShell detect` を実行し、新たな不整合が無いことを確認 | なし |

`02` と `03` の表名に含まれる日付（`20260925`）は、実行日に合わせて書き換えること。
`03` は作業表を**永続表として残す**（是正した行を事後に特定できる記録として使うため。
`04` の検証項目 (2)(3) もこの表を参照する）。

## 検証の期待結果（`04_verify.sql`）

1. `remaining_duplicates` = 0 — 本欠陥由来の重複が残っていない
2. 各行の `active_rows` = 1 — 対象だった選手の連動先カテゴリーが1件ずつ残っている
   （是正で対応ペアそのものが消えていない）
3. `unexpectedly_removed` = 0 — 是正対象以外の連動行を巻き添えにしていない

## ロールバック

`03` の UPDATE のみを戻す場合:

```sql
UPDATE category_racers c
JOIN lineage_dup_fix_targets_20260925 t ON t.id = c.id
SET c.deleted = 0, c.deleted_date = NULL, c.modified = NOW();
```

想定外の広範な変更が起きた場合は、バックアップ表から該当行を復元する:

```sql
UPDATE category_racers c
JOIN category_racers_bk_20260925 b ON b.id = c.id
SET c.deleted = b.deleted, c.deleted_date = b.deleted_date,
    c.cancel_date = b.cancel_date, c.modified = b.modified
WHERE c.deleted <> b.deleted;
```

## 実行方法（参考）

```
docker exec -i cyclox2_mysql bash -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" cyclox2 -t' < 01_detect_duplicates.sql
```

本番環境での接続情報は環境に合わせること。`03` と `04` は `lineage_dup_fix_targets_20260925` を
共有するため、作業表を永続表にしてある（同一セッションである必要はない）。
