==========================================================
 降格処理 本番反映 手順（A案: 検証済みSQLを本番へ適用）
==========================================================

前提:
- ローカルで検証済みのSQL一式（outputs/ 配下）を本番DBへ同手順で適用する。
- 本番の接続情報（ホスト/ユーザー/パスワード）は本書に書かない。
  運用者が安全な経路（.env / 環境変数 / 資格情報管理）から用意する。
- 変更対象は category_racers テーブルのみ。フルダンプ/レストアは行わない。

----------------------------------------------------------
0. 準備
----------------------------------------------------------
[ ] 本番DBのバックアップを取得する（必ず最初に）。
      例: mysqldump --single-transaction -u <user> -p cyclox2 > backup_YYYYMMDD.sql
[ ] 適用するSQLを用意する（ローカル outputs/ から本番作業環境へ安全に転送）:
      00_dup_fix.sql（重複修正・必要時のみ）
      c1_koukaku.sql / c2_koukaku.sql / c3_koukaku.sql
      m1_koukaku.sql / m2_koukaku.sql / we1_koukaku.sql
[ ] パスワードは環境変数で渡す（コマンドラインに平文で書かない）:
      export MYSQL_PWD="<本番の DB パスワード>"

----------------------------------------------------------
1. 重複修正（00_dup_fix.sql がある場合のみ）
----------------------------------------------------------
[ ] START TRANSACTION;
[ ] SOURCE 00_dup_fix.sql;
[ ] 影響行数・対象racerの状態を確認（想定どおりか）。
[ ] OK なら COMMIT; / 異常なら ROLLBACK;

----------------------------------------------------------
2. カテゴリーごとに適用（c1 → c2 → c3 → m1 → m2 → we1 の順）
----------------------------------------------------------
各カテゴリーで以下を1セットとして実施する。

[ ] START TRANSACTION;
[ ] SOURCE <cat>_koukaku.sql;
[ ] 検証（COMMIT前に必ず確認）:
      - 降格先INSERT件数が期待数と一致するか
        SELECT COUNT(*) FROM category_racers
         WHERE category_code='<降格先>' AND reason_id=4
           AND reason_note='2025-26シーズン成績の降格処理による'
           AND apply_date='2026-04-01';
      - 先頭と末尾の racer の所属状態（旧カテゴリー終了＋降格先付与）を目視。
[ ] 想定どおり → COMMIT; / 異常 → ROLLBACK; して原因確認

  期待件数（2025-26）:
    c1: C1→C2  93     m1: CM1→CM2  48
    c2: C2→C3 107     m2: CM2→CM3 113
    c3: C3→C4 202     we1: CL1→CL2 20
  ※多重行のracerがいる場合、UPDATE件数はINSERT件数より多くなることがある（正常）。

----------------------------------------------------------
3. 全体の最終確認
----------------------------------------------------------
[ ] 降格先別件数: C2:93 / C3:107 / C4:202 / CM2:48 / CM3:113 / CL2:20（計583）
[ ] 二重降格 0件（同一racerが2回INSERTされていない）
[ ] 降格者が旧カテゴリーにアクティブ行を残していない（全0）
      ※ sql/03_verify.sql 相当のクエリで確認
[ ] ressys（結果閲覧）でランキング表示が想定どおり更新されたか確認

----------------------------------------------------------
4. 異常時
----------------------------------------------------------
- COMMIT前の異常は ROLLBACK で戻す。
- COMMIT後に問題が判明した場合は、0.で取得したバックアップから復旧を検討。

（数値・対象シーズンは 2025-26 実績。次年度は runbook.md の「次年度の更新点」に従い更新）
